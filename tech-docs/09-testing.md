# 9. Тестирование

## Устройство

- Тесты лежат в `tests/`: страница `tests/index.html` и наборы `*.test.js` (36 наборов, около 2600 проверок).
- Страница загружает приложение во фрейм с параметром `?test`. В этом режиме у приложения отдельное хранилище (`habit-tracker-test-*`), выключены облако и уведомления, а экспорты всех модулей доступны как глобальные имена.
- Набор — обычный скрипт: готовит данные (`show(...)`, `normalize(...)`), действует через DOM или функции и записывает результаты `ok(название, условие, подробности)`.
- В каждом наборе дополнительно проверяется отсутствие ошибок на странице и нарушений CSP.
- Список наборов — массив `SUITES` в `tests/index.html` (название + файл).

## Запуск

| Команда | Что делает |
|---|---|
| `powershell -ExecutionPolicy Bypass -File tests\run.ps1` | Все наборы в Edge или Chrome без окна (через протокол отладки) |
| `... run.ps1 -Only "plan,summary"` | Только указанные наборы |
| `... run.ps1 -Live` | Тесты из ветки `main` против опубликованного сайта |
| `powershell -ExecutionPolicy Bypass -File tests\webkit.ps1` | Те же наборы в WebKit (движок Safari) через Playwright |
| `tests\serve.ps1`, затем http://localhost:8766/tests/ | Запуск в обычном браузере с выводом на странице |

Для WebKit нужен Node.js. Playwright и движок WebKit скачиваются автоматически при первом запуске (`tests/package.json`, папка `node_modules` не попадает в git).

## Порядок работы

- После каждой задачи запускаются наборы, которых касалась правка (`-Only`).
- Полный прогон — перед публикацией. Публикация без прошедших тестов недопустима.
- Найденная ошибка сначала закрепляется проверкой, потом исправляется.

## Что покрыто

| Область | Наборы |
|---|---|
| Привычки, отметки, расписание, перевыполнение | `app`, `regress`, `v1`, `schedule`, `overflow`, `plan` |
| Карточка привычки, сводка, заметки, жесты | `notes`, `summary`, `gestures` |
| Задачи | `tasks`, `tasks0`, `tasksA`–`tasksF`, `tasksM`, `tasksR`, `tasksS`, `taskparse` |
| Цели | `goals`, `goals3` |
| Облако, личное, общие списки, аккаунт | `sync`, `private`, `shared`, `account`, `smart` |
| Интерфейс, адаптивность, вёрстка, анимации, цвета | `ui`, `responsive`, `layout`, `motion`, `colors`, `redesign`, `guide` |
| Безопасность и тексты | `audit` |

`layout.test.js` обходит все экраны и окна на ширинах 320, 393 (светлая и тёмная тема) и 768 px. Он ищет обрезанный текст, текст, перекрытый другими элементами, и горизонтальную прокрутку. `responsive.test.js` проверяет 10 размеров экрана: цели касания 44 px, шрифт полей ввода, заголовки экранов, окна.

## Особенности WebKit

WebKit для Windows — тот же движок, что у Safari, но не iPhone. Тесты написаны так, чтобы работать в обоих движках:
- касания создаются через `new Touch()`, а если его нет — через событие с полями `touches`;
- подсказка клавиши Enter проверяется по атрибуту `enterkeyhint`;
- проверка поля выбора времени пропускается, если браузер не поддерживает `type="time"`.

Окончательная проверка интерфейса — на iPhone.
