# 10. Разработка и выпуск

## Окружение

- Сборка не нужна: достаточно любого статического сервера. Для тестов есть `tests\serve.ps1`.
- На `localhost` service worker отключается сам, поэтому изменения видны сразу.
- Для тестов в WebKit нужен Node.js (`winget install OpenJS.NodeJS.LTS`).

## Ветки

| Ветка | Назначение |
|---|---|
| `dev` | Все правки |
| `main` | Опубликованная версия; из неё GitHub Pages собирает сайт |

Коммит, отправка и слияние выполняются только по команде владельца «публикуй».

## Версия

- Схема: `X.Y` с буквенными суффиксами между выпусками (`3.2d`, `3.3`). Метку выбирает владелец при каждой публикации.
- Версия меняется только при публикации, во всех местах сразу:
  - `sw.js` — `VERSION`;
  - `index.html` — `styles.css?v=…` и `app.js?v=…`;
  - `app.js` и все `import` в `js/*.js` — `?v=…`.
- После замены поиском проверяется, что старой метки не осталось. Тест «all modules loaded with app version» проверяет совпадение.

## Порядок публикации

1. Убедиться, что текущая ветка — `dev`, закоммитить правки.
2. `git fetch`; проверить, что `dev` и `main` не отстают от `origin`. Если отстают — остановиться.
3. Полный прогон тестов `tests\run.ps1`. Не прошли — остановиться.
4. Обновить версию во всех местах, проверить поиском.
5. Коммит «Release X» в `dev`.
6. Показать владельцу сообщение коммита и список файлов, которые уйдут в `main`, и дождаться подтверждения.
7. `git checkout main`, `git merge dev`, `git push`.
8. Проверить, что `main` чистая и совпадает с `origin/main`.
9. `git checkout dev`, `git push` ветки `dev`.

Автор коммитов — `f3indlich`. В сообщениях коммитов и в коде нет следов автоматической генерации.

## Развёртывание

- **Сайт:** GitHub Pages из `main`. `_config.yml` исключает из сайта `tests/`, `supabase/`, SQL-файлы, `README.md`, `demo-data.json` и `tech-docs/`.
- **Обновление у пользователей:** новый `sw.js` с другой версией скачивает новую оболочку и удаляет старые кэши. Если открыта старая версия, достаточно закрыть и снова открыть приложение.
- **Supabase:** SQL-файлы выполняются вручную в SQL Editor (повторный запуск безопасен); функция `send-reminders` разворачивается из `supabase/functions/`. Файлы сервера меняются только по явному запросу владельца.

## Проверка после публикации

- `sw.js` на сайте отдаёт новую `VERSION`.
- `tests\run.ps1 -Live` проверяет опубликованный сайт тестами из `main`.
- Ручная проверка на iPhone 15 Pro.
