# 7. Безопасность

## Модель угроз

| Угроза | Защита |
|---|---|
| Внедрение скриптов через данные (название привычки, запись в общем списке) | Все пользовательские строки проходят через `esc()` перед вставкой в разметку; цвета проверяются шаблоном; строгая CSP |
| Подмена внешней библиотеки на CDN | Закреплённая версия и проверка целостности (SRI), разрешён только этот адрес скрипта |
| Чтение чужих данных в облаке | RLS на всех таблицах: доступ только к своим строкам и спискам, где пользователь участник |
| Изменение служебных полей в общих списках | Триггеры-сторожа запрещают менять владельца, список, автора и даты |
| Перебор кодов приглашений и злоупотребление вступлением | Одноразовые коды, действующие 48 часов; журнал попыток вступления за сутки для ограничения частоты |
| Чужой вызов функции напоминаний | Секрет `x-cron-secret`, сравнение за постоянное время |
| Встраивание приложения в чужой сайт (кликджекинг) | Проверка `framedByOther`: приложение прячется и предлагает открыть его напрямую |
| Утечка секретов | В репозитории только публичный ключ Supabase и публичный VAPID-ключ; сервисные ключи — в секретах функции |
| Посторонний человек с телефоном видит личное | PIN-замок «Личного» с блокировкой по бездействию (2 минуты) и задержкой после неверных попыток |

## Политика безопасности содержимого (CSP)

Задаётся мета-тегом в `index.html`:
- `default-src 'self'`;
- `script-src 'self'` + один адрес библиотеки Supabase;
- `style-src 'self' 'unsafe-inline'` + Google Fonts (стили внутри элементов нужны для цветов и размеров);
- `connect-src` — только свой адрес и проект Supabase (HTTPS и WSS);
- `object-src 'none'`, `base-uri 'self'`, `form-action 'self'`, `worker-src 'self'`.

Тесты отслеживают нарушения CSP во всех наборах: каждое нарушение — провал.

## PIN и «Личное»

- PIN 4–6 цифр. Хранится как PBKDF2-SHA-256, 200 000 итераций, случайная соль; сравнение хэшей за постоянное время.
- После неверных попыток растёт задержка перед следующей попыткой.
- **Ограничение:** PIN скрывает личные записи в интерфейсе, но данные не шифруются ни в `localStorage`, ни в облаке. Человек с доступом к хранилищу браузера или к аккаунту Supabase может прочитать их.

## Вход

- Вход без пароля: ссылка или код из письма.
- Сейчас используется implicit-поток: токен приходит во фрагменте адреса и сразу удаляется из него. Более строгий вариант — PKCE (по решению владельца не применяется).

## Известные ограничения

- GitHub Pages не позволяет задать заголовки ответа, поэтому CSP — только мета-тегом, а `frame-ancestors` недоступен (заменён проверкой в коде).
- `style-src 'unsafe-inline'` оставлен ради стилей в атрибутах; скрипты при этом встраивать нельзя.

## Проверки

- Набор «Безопасность, иконки, статистика, тексты» (`audit.test.js`): экранирование пользовательских строк, корректность всех путей SVG. Нарушения CSP отслеживаются в каждом наборе.
- `supabase-shared-lists-test.sql`: проверка политик общих списков на реальной базе.
