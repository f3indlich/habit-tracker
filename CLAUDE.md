# Правила работы с проектом

## Ветки и публикация
- Все правки делай в ветке dev. Ветку main не трогай.
- Не выполняй git commit, git push и слияние веток без моей явной команды «публикуй».
- Опубликованная версия — это ветка main. Сайт публикуется из неё.

## Версия приложения
- Версию (сейчас 1.00a) меняй только при публикации, а не при каждой правке.
- Версию нужно менять во всех местах: sw.js, index.html (styles.css?v=... и app.js?v=...), app.js и все import в js/*.js.
- Тест «all modules loaded with app version» проверяет, что метки совпадают.

## Тесты
- Перед публикацией запускай тесты: powershell -ExecutionPolicy Bypass -File tests\run.ps1
- Публикация без прошедших тестов недопустима.

## Порядок публикации (только по команде «публикуй»)
1. Проверь, что я в ветке dev, и закоммить все текущие правки в dev.
2. git fetch, затем проверь, что dev не отстаёт от origin/dev и main не отстаёт от origin/main. Если отстают, остановись и сообщи.
3. Запусти тесты. Если тесты не прошли, остановись и сообщи.
4. Обнови версию во всех местах и проверь поиском, что старой версии не осталось.
5. Закоммить изменения в dev с сообщением «Release X».
6. Покажи мне сообщение коммита и список файлов, которые уйдут в main, и дождись подтверждения.
7. После подтверждения: git checkout main, git merge dev, git push.
8. Проверь, что git status на main чистый и main совпадает с origin/main.
9. git checkout dev, затем git push ветки dev.

## Остальное
- Перед крупными правками кратко описывай план и жди одобрения.
- Не меняй файлы в supabase/, config.js и SQL-файлах без явного запроса.
